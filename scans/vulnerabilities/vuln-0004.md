## Description

Svelte devalue versions 5.1.0 through 5.9.2 contain a cross-request process memory disclosure vulnerability where stringify and uneval serialize a typed array by emitting its entire backing ArrayBuffer rather than the slice view. When serializing a Node Buffer sharing a process-wide pool, up to 64 KB of uninitialized or unrelated process memory may be leaked.

## Evidence

**Advisory evidence:** `CVE-2026-92708` applies to `devalue` at installed version `5.9.1`. The advisory is fixed in `5.9.3`.

**Transitive dependency:** introduced by the direct dependency `@sveltejs/kit@2.70.3`.

**Dependency chain:** `@sveltejs/kit@2.70.3 > devalue@5.9.1`

**Usage analysis:** not imported by application code. Searched src/ for imports of devalue using rg 'devalue' src/. No direct import or symbol usage was found in application source code. The package is pulled in transitively by @sveltejs/kit (v2.70.3) and svelte (v5.56.10). This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

In vulnerable configurations returning Node Buffers in SSR load() functions, up to 64 KB of shared memory from other concurrent requests could be leaked in rendered HTML responses. In this codebase, devalue is not directly imported.

## Technical Analysis

In devalue 5.1.0-5.9.2, Node Buffers allocated from the shared 64 KB pool retain the entire pool buffer reference during serialization. When rendered into SSR payloads, adjacent memory bytes from prior requests sharing the pool may be serialized into the output HTML.

## Contextual CVSS

The application codebase does not directly import devalue or pass Node Buffer objects through page load() functions. While @sveltejs/kit@2.70.3 transitively depends on devalue@5.9.1, no application route handler (src/routes/*) constructs or returns pooled raw Node Buffers. Consequently, impact metrics are set to None.

## Remediation

Run `npm update devalue` or update `@sveltejs/kit` to ensure `devalue` resolves to `>= 5.9.3`.

## Assumptions

Assumes the application does not serialize raw Node Buffer objects via SvelteKit SSR load functions.
